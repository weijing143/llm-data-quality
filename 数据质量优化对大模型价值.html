DATA-CENTRIC AI · 深度解读

数据质量优化，
到底给大模型带来了什么价值？

把"数据要干净"这句口号拆成可计量的三层账：它改写缩放律的下界（模型最多能多好）、 决定同样算力买到多少能力（花多少钱达到同一分数）、也划定模型永远学不会的边界（分布里没有的东西学不出来）。 下面这条主线依次回答：机制上为什么有效 → 质量怎么被定义和度量 → 工程上怎么变成工序 → 案例里兑现了多少 → 投入产出怎么算 → 什么情况下它会失效。

00

先给结论：六句话讲完

如果只看一屏，看这六条。它们也是后面所有章节的骨架。

01 · 它改动的是缩放律

质量不是"锦上添花"，它改的是常数项

缩放律里那个降不下去的不可约损失 E，本质由数据决定。清洗、去重、筛选的真正作用，是把这条曲线整体往下推，而不是单纯把训练拉长。

02 · 数据墙之后唯一的杠杆

同样的数据重复喂，收益会衰减

在高质量语料稀缺、重复训练不可避免的今天，"更多"的边际收益在下降，而"更好"的边际收益还存在。但两者不能互相替代：实验显示重复 ≤4 个 epoch 时损失变化可忽略、再往上加算力的价值衰减到零；而重复导致退化时，换成更高质量的数据也救不回来。

03 · 它可以换算成钱

用更少 token 达到同一分数

数据优化的产出可以写成"等效算力倍数"：同样的评测分数，优化后的数据配方只需要原配方的一部分算力，差的就是省下的 GPU 小时。

04 · 质量是相对量

对谁、为什么能力而优？

质量没有绝对标准：小模型消化不了噪声，大模型吃不饱"太简单"的数据。脱离目标能力与模型规模谈质量，等于没有指标。

05 · 最大的风险是洗过头

过滤器会连同长尾一起删掉

实证是双向的：主过滤对低资源语种多数有益，但启发式过滤收益不稳定甚至有害；脚本过滤会误删混写样本。更严的过滤常常换来更高分与更差的行为安全，且损失往往几轮之后才暴露。

06 · 最终裁判是评测

污染的测试集会让"提升"变成自欺

如果测试样本早就在训练语料里，任何数据质量改进的结论都不可信。干净评测集与干净训练数据同等重要。

01

机制：为什么"数据更好"能等价于"算力更多"

缩放律给出的是"投入—损失"的经验曲线。数据质量之所以有价值，是因为它同时作用在曲线的三个位置上。

L(C) = E + A·N-α + B·D-β N=参数量，D=数据量（token），C≈6ND 为训练算力。E：不可约损失（数据决定的下界） · A：模型侧系数 · B：数据侧系数
机制 A · 信噪比

噪声样本给出互相冲突的梯度

乱码、模板残留、机器翻译腔、事实错误的段落，会让模型在同一个上下文里学到互相矛盾的目标。结果不是"学不会"，而是把容量与算力花在了拟合噪声上——表现为同样步数下损失下降更慢、泛化更差。

机制 B · 去重

重复内容等于偷偷改了权重

语料里的重复文档，在梯度层面等价于给这部分内容加权。模型因此更倾向于逐字记忆而不是抽象规律；去重的直接收益是"同分数用更少训练步数"，次要收益是降低逐字复现与隐私泄露风险。子串级去重的经典结果显示，模型输出记忆文本的频率可降低约 10 倍，同时消掉了标准验证集中超过 4% 的训练-测试重叠（Lee et al., ACL 2022）。

机制 C · 配比

分布决定算力花在哪里

各领域的边际收益不同，最优混合比例还会随模型规模与训练阶段改变。配比做得好，等于把同样的 FLOPs 从"已经学会的部分"搬到"还不会的部分"，这是数据侧最纯粹的效率收益。

这只是示意模型，不是实测数据。它演示的是论文里反复出现的定性结论：数据质量改动的是 E（下界）与 B（数据效率系数），因此曲线整体下移而不是沿同一条曲线滑动。真实数值必须用你自己的消融实验拟合。
这不是新观点——2020 年就这么干了：GPT-3 的训练配比并非按数据集大小比例采样：Common Crawl 有 410B token，训练时只过了 0.44 个 epoch；WebText2（19B token）过了 2.9 个；Wikipedia（3B token）过了 3.4 个。论文原话是"我们视为更高质量的数据集被更频繁地采样……本质上是接受少量过拟合，以换取更高质量的训练数据"。换句话说：按质量加权、主动接受重复训练，是十多年前就已经确立的默认策略，今天的"数据质量工程"只是把它做得更精细、更可度量。
更强的说法 · 数据剪枝

数据选择可以"击败幂律"，但前提是度量足够准

Sorscher 等（2022）主张用剪枝改写缩放曲线：按可学习性分数选数据，可用显著更少的数据达到同样性能。但同一工作给出了残酷的下界——当剪枝度量不完美时（夹角 10° / 20°），最多只能保留 24% / 46% 的数据才不损失性能。更反直觉的是剪枝策略随数据量反转：数据充足时保留最难的样本，数据稀缺时反而应保留最简单的。

约束条件 · 数据受限

重复训练有上限，而且上限不固定

在最多 400 次训练、9B 参数、900B token 的规模上，重复 ≤4 个 epoch 相对唯一数据的损失变化可忽略，之后新增算力的价值衰减到零；参数越大衰减越快，所以数据受限时应优先增加 epoch 而不是加大模型。但后续研究给出反例：小数据集重复 256 轮时显著退化，且换用更高质量的数据也无法缓解——2025 年的理论进一步指出"可重复上限"取决于数据集绝对规模，而非固定的 4 轮。

把质量写进缩放律

质量可以被建模，但结论有适用规模

有研究把"有效数据量"写成随多样性与合成比例指数缩放的项，与真实准确率的相关性达 0.83；另一项 2,000+ 模型的大规模实证发现，去重、启发式过滤与 LLM 改写会同时改变缩放律的系数与指数，最优 token/参数比因干预手段不同而相差数量级。但该建模研究的规模是 25M–1.5B 参数，且观察到参数量超过约 1.5B 后总量重新占主导——小模型上的数据质量结论，不能直接外推到大模型。

02

定义：把"质量"拆成可度量的四层与五维

"高质量数据"在不同团队口中含义完全不同。工程上必须把它拆到能写进验收标准的粒度。

可操作定义：数据质量 = 单位 token 带来的有效能力增量。 写成式子就是 quality ≈ Δ能力 / Δtoken。它有两个直接推论：① 质量必须相对于目标能力才有意义； ② 已被模型掌握的内容，其增量趋近于零——这也是"重复数据收益递减"的另一种说法。
L1 · 可发布

合规与安全

  • 版权与许可（robots、许可清单）
  • 个人隐私 PII 去除
  • 有害内容与滥用风险
  • 数据来源可追溯性与审计
L2 · 可训练

形式可用

  • 正文抽取正确（不混入导航/模板）
  • 编码、语言、乱码识别
  • 重复行、样板句、占位符剔除
  • 长度与结构分布可控
L3 · 可学

信息密度

  • 知识密度与事实正确性
  • 难度分布（不是越难越好）
  • 跨文档去重（含改写与翻译重复）
  • 教育/专业价值打分
L4 · 有用

任务价值

  • 与目标能力分布对齐（推理/代码/工具调用）
  • 含推理链、多步解题、可验证答案
  • 难度落在模型"最近发展区"
  • 与环境/验证器可闭环
五个正交维度

质量向量，而不是一个分数

  • 正确性：事实、代码可运行、答案可验证
  • 多样性：主题、风格、语言、视角、长度
  • 信息量／难度：对当前模型仍有梯度信号
  • 独立性：与语料内其他样本不重复
  • 对齐度：与目标任务的分布距离

把质量压成单一标量（例如一个分类器分数）时，其余四维会被静默优化掉——这是绝大多数"数据质量事故"的根因。

三个反直觉

常见误解

  • "质量 = 干净"：干净只是 L2，清洗完的数据依然可能零信息量。
  • "质量是绝对属性"：同一份数据对 1B 和对 70B 的价值完全不同，对小模型是噪声、对大模型是常识。
  • "质量高就可以少要量"：多样性只能靠规模提供。过度筛选会把语料变成"同一批事实的各种说法"，模型随之变得窄而自信。

工程：把质量变成九个可验收的工位

专题一 · 去重

三级去重：成本差一个数量级，收益也差一个层级

级别抓什么成本风险
精确完全相同的文档/段落（哈希、后缀数组）低漏掉轻微改写
近似高重叠的 n-gram 重复（MinHash + LSH 等）中阈值选择影响召回与误杀
语义同义改写、翻译重复、同事实多表述（嵌入聚类）高最容易误杀"同主题不同信息"

公开配方参考：FineWeb 用文档 5-gram + 14 桶 × 8 哈希（目标"至少 75% 相似"）；NeMo Curator 新版默认 char_ngrams=24、20 bands、13 hashes/band——band 越多、每 band 哈希越少，判定越严格。

一个必须记住的反例：FineWeb 曾尝试全局迭代去重，结果最老的快照被删掉多达 90%，语料从约 36T 掉到 4T；而逐快照独立去重只掉到约 20T，效果反而更好——保留下来的 10% 质量差于被删掉的 90%（广告、关键词堆砌更多）。语义去重（SemDeDup）在视觉任务上可删掉约 50% 数据而性能几乎不降，去重自身成本约为训练的 1%。

专题二 · 质量打分

启发式、轻量分类器、LLM 裁判的三层取舍

  • 启发式规则：零推理成本、可解释、可审计，但对"信息密度"几乎无感。
  • 轻量分类器（如 fastText 类）：全量语料可承受，需要少量标注或弱监督样本来定义"好"。
  • 嵌入 / LLM 打分：最贴近人类判断，可用于蒸馏出一个廉价分类器，而不是直接筛全量数据。

成本结构的标准做法：FineWeb-Edu 用 Llama-3-70B 给 46 万条样本打 0–5 教育性分，训练一个线性头（阈值 3 时验证 F1 82%），再用它给 15T token 全量打分——推理约 6,000 H100 小时。教师很贵、学生很便宜，钱要花在定义"好"上，而不是逐条问大模型。

专题三 · 合成数据

改写、自蒸馏与验证器

合成数据是"用算力换数据"的手段：把低质但真实的原始文本改写为结构化、教学化的版本，或直接生成带验证信号的推理轨迹。关键不在于生成，而在于验证——可执行验证（代码跑通、答案对得上、工具调用成功）才是质量闭环，否则只是把噪声换了个说法。

专题四 · 度量与验证

数据配方要靠实验说话

  • 小规模消融：固定算力，只换数据配方，看同预算下的损失/分数。
  • 缩放律外推：用多档规模拟合，预测大数据预算下的排序是否稳定。
  • 污染体检：n-gram 重叠、干净重写测试集、时间切片验证。
  • 数据归因：定位某个能力来自哪部分数据（影响函数/消融桶）。

长上下文数据
ProLong		 两阶段各 20B token，把上下文从 64K 扩到 512K——仅为 Llama-3.1 长上下文数据预算的 5% 40B token HELMET@128K 平均 49.4，高于 Llama-3.1-8B 的 46.5；长:短数据最佳比例 60:40；长数据来源 Books:Code = 1:1 最好（54.6）；SFT 中混入合成长指令数据有害（0%→55.7、10%→53.9、50%→43.3） 长上下文能力同样由数据配比决定；且"只看向大海捞针 / perplexity"会严重误导评估
共同点 1

先解决"有没有"，再解决"好不好"

所有案例的第一步都是去重与正文抽取这种"低垂果实"，收益最大且几乎无副作用。

共同点 2

用小模型做数据裁判

成功的配方几乎都用一个小模型（或分类器）去近似"人类会怎么判断这份数据"，再全量应用。

共同点 3

收益需要可验证的评测

案例都配有干净评测与同算力基线；缺少这两样时，数据质量的故事无法证伪，也就无法复用。

05

投入产出：三本账与一个决策树

数据质量的收益不是"感觉更好"，它可以被折算成算力、人力与风险三类成本的对冲。

账本一 · 算力

同等效果下的 token / FLOPs 节省

把"达到同一评测分数所需的训练算力"作为统一货币：优化前的配方需要多少 GPU 小时，优化后需要多少，差额就是收益。

  • 通用换算：训练算力 ≈ 6 × 参数量 × token 数
  • 数据侧系数改善 → 曲线整体下移 → 同分数更少算力
  • 注意：省下来的算力若不投入新一轮实验，收益不会自动兑现
数据处理 ≈1.6%一次前沿训练 run

FineWeb 整个数据处理项目约 80,000 H100 小时，对照一次约 500 万 GPU 小时的训练运行——数据侧的账，通常比训练侧的账小两个数量级。另一个可核验的口径：DCLM-7B 在 53 项任务上与 Llama 3 8B 相当，而训练算力少 6.6 倍；相对 MAP-Neo，MMLU 高 6.6 个百分点同时省 40% 算力（注意：同一篇论文里的两个"6.6"含义不同，网上常被混引）。

账本二 · 人力与流水线

清洗成本 vs 训练成本

数据流水线的钱花在三处：工程与算力（抽取、去重、分类器推理）、标注与评审（定义"好"、评估配方）、反复实验（消融）。

  • 分类器推理是可控的固定成本，随语料线性增长
  • 人工评审贵在定标准，适合小样本、高杠杆
  • 消融实验是唯一能把"数据好不好"变成数字的方式
账本三 · 风险

不投数据质量的隐性账单

  • 评测污染 → 决策建立在虚高分数上，返工成本极高
  • 版权/隐私问题 → 模型下架与合规成本
  • 记忆化与逐字复现 → 品牌与法务风险
  • 长尾能力缺失 → 上线后由用户发现，修复成本最贵
1
评测可信吗？
不可信 → 先修评测：污染体检 + 干净复测集。此时做任何数据优化都无法判定效果，属于无效投入。
2
固定算力、只换数据配方，分数会动吗？
会动 → 数据侧还有空间，值得继续投；几乎不动 → 瓶颈更可能在算法、规模或后训练，先别在数据上加预算。
3
错误集中在知识盲区、格式与覆盖度上吗？
是 → 优先做抽取、去重、域覆盖与合成增密，收益路径清晰；否（错在多步推理、交互与长程一致性） → 需要的是环境反馈与推理轨迹数据，而不是更多网页文本。
4
语料已高度同质、长尾与低资源部分被反复剔除？
是 → 继续筛选的边际收益趋近于零，下一步应转向多样性采集与合成数据质量，而不是更严的过滤器。
✕
触发红线就停下
长尾留存率跌破下限、污染复测分数与主分数背离、去重误杀代表样本——出现任一情况，先回滚配方再谈优化。
值得重投的信号

什么时候数据质量是瓶颈

  • 同算力下换配方就能显著改变分数（说明数据侧还有空间）
  • 错误集中在知识盲区或特定格式，而非推理深度
  • 目标能力的样本在语料里占比过低
  • 已有可信评测与小规模代理实验能力
不值得重投的信号

什么时候它不是瓶颈

  • 目标能力靠的是算法/架构/后训练机制，而非数据分布
  • 评测本身不可信，任何改动都无法判定好坏
  • 需要的是环境交互与反馈闭环，静态语料再干净也补不上
  • 数据已高度同质，继续筛选只是重复剔除同一批样本
一句话的 ROI 判据：如果"花一周做数据实验"能换来"少训一个数量级的 token 或显著改变能力分布"，它就值得； 如果数据改动无法在可信评测上被稳定观测，那它不是优化，只是信仰。

两个可用的量级参考：① 效率倍数 m 与盈亏平衡——一篇被广泛引用的立场文章提出：若数据配方带来 m 倍 token 效率，最多可以把 1 − 1/m 的算力预算挪到数据侧仍能打平（m=6 时约 83%）。这是一阶近似，不是精确结论。 ② FineWeb 整个数据处理项目约 80,000 H100 小时，约为一次 500 万 GPU 小时训练运行的 1.6%。 公开项目自报的效率倍数多在 6–8× 量级（FineWeb-Edu ≈7.9×、BeyondWeb ≈7.7×、OLMo 3 ≈6×），但这些数字口径不一、多为立场文章换算，不可直接横比。
06

边界与反面：质量优化会在哪里反咬一口

这一节比前面更重要：数据质量的工作一旦做错，损失是静默的、累积的、越训越难回头的。

风险 1 · 洗过头

过滤器会连同长尾一起删掉，而且证据是双向的

Nemotron-CC 团队直接点名：FineWeb-Edu、DCLM 这类激进模型过滤的代价是移除约 90% 的数据，并不适合长 token 训练。跨语言研究的结论同样是双向的：主过滤对低资源语种多数有益（宿务语 +12%），但启发式过滤收益不稳定甚至有害（SIB200 平均 0.63→0.50）；脚本过滤会误删阿拉伯语/拉丁字母混写的代码切换样本。Wikipedia 上约鲁巴语因精确去重丢掉近 60% 文章。另有研究转述的结论是：过滤更严格的数据集下游分数更高，但模型更可能生成有毒内容。

风险 2 · 自噬

合成数据的近亲繁殖

Shumailov 等人在 Nature（2024）中证明递归训练于生成数据会导致模型崩溃，并主张这是生成模型的普遍现象；Gerstgrasser 等随即限定了它的适用条件——崩溃的真正分水岭是"替换旧数据"还是"累积保留真实数据与各代合成数据"，后者可以避免崩溃并给出与迭代次数无关的误差上界。所以工程上的反制条件不是"不用合成数据"，而是：累积而非替换、保留真实数据锚点、用验证器与多样性约束过滤合成样本。

风险 3 · 自欺

污染让分数虚高，但别把话说满

最硬的证据来自 GPT-3 自己的清理实验：PIQA 有 29% 样本被标记为可能污染，清理后绝对下降 3 个百分点（相对 4%）；Winograd 标记 45%、清理后降 2.6%；LAMBADA 差异在 0.5% 以内。GSM1k 的干净重写版本上，最差的模型相对掉 13%，且"生成原题的概率"与落差相关（Spearman r²=0.32），但前沿模型落差接近零（GPT-4 仅 −0.7%）。论文自己也强调：所有模型仍能泛化，污染很可能不是过拟合的全部原因。另外，常用 n-gram 检测对改写过的污染假阴性很高——简单改写或翻译即可绕过；而受控实验显示，当源句与译文同时出现在训练语料中时，翻译 BLEU 最多可虚高 30 分，且 8B 模型的虚高幅度是 1B 的 2.5 倍。

风险 4 · 错配

优化了错误的维度

把"平均文档质量分"当成目标函数，会得到一批干净、正确、却高度同质的文本；模型在基准上更稳，在真实长尾任务上更脆。指标错了，优化越努力越糟。

06+

争议清单：同一个问题，文献并不一致

数据质量领域最容易犯的错，是把某一篇论文的结论当成普遍规律。下表列出五组真实存在的冲突——写方案时请按自己的数据预算与评测重新验证。

问题一种结论另一种结论怎么理解
去重到底有没有用？ Lee 等（2021）：困惑度、训练步数、记忆化三重收益，逐字复现降低约 10 倍 后续工作报告去重未改善下游；FineWeb 发现全局去重几乎无提升，且删掉的那部分质量更高 差别在粒度与范围：子串级、逐快照去重有收益；跨快照的全局迭代去重会连带误伤
该保留哪些样本？ Sorscher 等：数据充足时保留最难的样本最有效 同一工作：数据稀缺时应保留最易的样本；而"筛掉 90% 反而更好"的结论也真实存在 剪枝策略依赖数据预算与度量准确性，不存在通用最优；换个数据规模结论就会反转
"少而精"是否全面更好？ AlpaGasus：9,229 条在四个开放式测试集上全面优于 52,002 条 同一篇论文：在 MMLU 等知识类基准上，全量数据反而更高 收益出现在筛选目标对应的能力上；筛选指标即收益边界
重复多少轮还安全？ Muennighoff 等：重复 ≤4 个 epoch 损失变化可忽略 Xue 等：小数据集重复 256 轮显著退化，且换更高质量数据也无法缓解；2025 年理论认为上限取决于数据集绝对规模 "4 轮"是特定规模下的经验点，不是常数；数据越大越耐重复
高质量数据能替代规模吗？ phi 系列：小模型 + 精选/合成数据可超过参数与数据大得多的模型（论文口径：模型小 10 倍、数据小 100 倍） Xue 等：重复场景下高质量数据救不回退化；质量缩放建模显示参数量超过约 1.5B 后总量重新占主导 质量与数量更接近乘法关系而非替代关系：质量决定同样的量能买到多少，数量决定天花板在哪
实践上的护栏：① 每轮筛选都记录"漏斗留存率"与各维度分布变化，而不只是最终分数； ② 为长尾/方言/低资源语言设留存下限，而不是让分类器自由裁量； ③ 合成数据必须锚定真实数据比例，并经过验证器过滤； ④ 所有评测结论必须在干净测试集上复现一次； ⑤ 保留"坏数据对照组"，否则无法知道筛选是否真的起了作用。
07

落地清单：从现在开始可以做的 12 件事

勾选做自查。前 4 项是"低垂果实"，几乎零风险；中间 4 项需要实验能力；最后 4 项是长期护栏。

0 / 12
漏斗指标

留存率

每一级过滤前后保留了多少文档与 token。异常下降通常是规则阈值写错或分类器漂移。

去重指标

重复率

文档级/段落级/子串级重复比例，以及去重前后的训练损失曲线对比。

分布指标

域与语言配比

目标分布 vs 实际分布的偏移量，含长尾与低资源语种的留存下限。

可信度指标

污染重叠率

训练语料与各评测集的 n-gram 重叠比例；同时维护一份"干净复测"分数。

08

术语速查：十个词看懂数据质量讨论

跨团队沟通时最容易各说各话的十个概念，这里给出"一句人话 + 它在本文里的位置"。

不可约损失 E

无论怎么加算力都降不下去的那部分损失，由数据分布决定。它是"数据质量"在数学上最直接的落点。

算力最优配比

给定算力预算时，参数量与数据量的最优搭配。它让"该训多大、该喂多少"变成可计算的问题，也让数据不足变成硬约束。

数据墙 / 数据受限

高质量公开语料被用尽、必须重复训练同一批数据的阶段。此时"更好"的边际收益高于"更多"。

去重（精确/近似/语义）

三个成本层级：完全相同、高重叠、同义改写。去重既是质量手段，也是隐私与记忆化风险的治理手段。

质量分类器

用少量人工判断或强模型打分做教师，蒸馏出的廉价全量过滤器。它决定了语料的"品味"，也继承了教师的偏见。

数据配比 / 混合律

各领域在训练集中占多少。最优配比随模型规模与训练阶段变化，属于"用算力分配换能力"的杠杆。

合成数据 / 自蒸馏

用模型生成或改写训练语料，等于用算力换数据。成立的前提是可验证与多样性，否则只是换了说法的噪声。

模型崩溃

递归使用自身输出训练导致分布尾部逐代塌缩的退化现象。学界对"是否必然"仍有争论，真实数据锚定与验证器是主要护栏。

数据污染 / 泄漏

评测样本出现在训练语料中，使分数虚高。它会让整个数据质量项目的结论失去意义，因此必须常规体检。

等效算力

把数据质量收益折算成"同分数所需算力倍数"的口径。它是让数据工作与算力预算在同一张表上比价的通用货币。

  • 一手Sorscher et al. 2022 · Beyond neural scaling laws: beating power law scaling via data pruning — 剪枝策略随数据量反转；度量不完美时的保留下界（夹角 10°/20° → 24%/46%）；自监督度量下丢弃 20% ImageNet 不损性能。
  • 一手Muennighoff et al. 2023 · Scaling Data-Constrained Language Models — 重复 ≤4 个 epoch 相对唯一数据损失变化可忽略；实验规模至 900B token、9B 参数、400 次训练。
  • 一手Xue et al. 2023 · To Repeat or Not To Repeat — 小数据集重复 256 轮显著退化，且换用更高质量数据无法缓解；扩充数据规模则不退化。
  • 一手DoReMi、RegMix、Data Mixing Laws — 用小模型代理搜索数据配比：+6.5 分 / 少用 2.6× 步数；512 个小模型预测最优混合；优化配比 ≈ 默认配比多训 48% 步数。
  • 一手Textbooks Are All You Need（phi-1）、Phi-3、Phi-4 — 1.3B/<7B token 达 HumanEval 50.6%；phi-3-mini 3.8B/3.3T 达 MMLU 69%；Phi-4 称"训练配方以数据质量为中心"。
  • 一手LIMA: Less Is More for Alignment 与 Deita — 1,000 条精选样本对 GPT-4 有 43% 回答"不差于对方"；Deita 仅 6K SFT + 10K DPO 达 MT-Bench 7.55、AlpacaEval 90.06%。
  • 一手AlpaGasus — 52,002 → 9,229 条（删 82.25%），开放式测试集全面更好、训练快 5.7 倍，但 MMLU 等知识基准上全量更高。
  • 一手SmolLM2 — 1.7B / 约 11T token 过训练，网页数据按 FineWeb-Edu 60% + DCLM 40% 配比，代码设 10% 上限；超过 Qwen2.5-1.5B 与 Llama 3.2-1B。
  • 一手The Llama 3 Herd of Models — 行级去重清除样板文本、n-gram 覆盖率与脏词计数做启发式过滤、fastText 覆盖 176 种语言 + 多语言质量分类器。
  • 一手ProLong · 长上下文数据配比 — 40B token 扩展到 512K，HELMET@128K 49.4 vs 46.5；长:短 = 60:40；SFT 混入合成长指令数据有害。
  • 一手把数据质量写进缩放律（有效数据量随多样性与合成度指数缩放） — 与真实准确率相关性 0.83；规模 25M–1.5B 参数，超过约 1.5B 后总量重新占主导。
  • 一手ICLR 2026 · 数据质量干预对缩放律的影响（2,000+ 模型实证） — 去重、启发式过滤与 LLM 改写会同时改变缩放律系数与指数，最优 token/参数比因干预手段相差数量级。
  • 一手Gopher（Rae et al. 2021）附录 A.1.1 与 T5/C4（Raffel et al. 2019） — 启发式过滤阈值的原始出处。注意：这两篇只给出定性结论（"显著改善下游表现"），没有可引用的百分比。
  • 一手GPT-3（Brown et al. 2020） — 质量加权的早期证据：Common Crawl 410B token 只过 0.44 个 epoch，Wikipedia 过 3.4 个；过滤用逻辑回归分类器（45TB → 570GB，约 400B token），而非 fastText。
  • 一手Gerstgrasser et al. 2024 · Is Model Collapse Inevitable? — 崩溃源于"新数据替换旧数据"的假设；改为累积真实数据与各代合成数据即可避免，测试误差有与迭代次数无关的有限上界。
  • 一手Nemotron-CC（ACL 2025） — 6.3T token；"激进模型过滤以移除 90% 数据为代价"；8B/1T 时高质量子集 MMLU 比 DCLM 高 5.6，8B/15T 优于 Llama 3.1 8B（MMLU +5）。
  • 一手Dodge et al. 2021 · Documenting Large Webtext Corpora — 评测输入在 C4 中的逐字命中率"从不足 2% 到超过 50%"；注意该文只做命中统计，没有"污染导致涨分"的实验。
  • 一手有效数据复用率理论（2025） — "数据集越大越耐重复"，可重复上限随数据规模增长，而非固定 4 个 epoch。
  • 一手ConTAM 与 机器翻译污染受控实验（ICML 2025） — 污染带来的"估计性能增益"可达 HumanEval 18%、BBH 25%；翻译任务上 BLEU 最多虚高 30 分（8B 的虚高是 1B 的 2.5 倍）。
  • 一手Data Contamination Quiz（TACL） — 用测验法估计污染比例：HumanEval 检出约 56%、DROP 约 43%、GSM8k-train 约 79%，远高于按公开报告值复算的结果。
